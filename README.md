# Alfa Insight — командный прототип

Персональная новостная аналитика для компаний: компания → лента → анализ с источниками → уточняющий вопрос.

Статус: работающий локальный прототип, основа для совместной разработки. **Node.js 24.13+ (24.x), TypeScript, Express, SQLite. Python для запуска не нужен.** Здесь находятся сервер, интерфейс, данные и документация проекта; отдельная вложенная копия приложения не требуется.

## С чего начать участнику

1. Запустить demo по инструкции ниже.
2. Прочитать [схему проекта и границы ролей](docs/TEAM_GUIDE.md).
3. Открыть [задачи по пяти ролям](TASKS.md).
4. Матвею, роль 3: [план Backend/RAG](docs/ROLE_3_BACKEND_RAG.md).
5. Сверять изменения с [архитектурой и текущим API](docs/ARCHITECTURE.md).

## Запуск

Команды выполнять из корня проекта, где лежит package.json. Нужны Node.js 24.13+ в ветке 24.x и npm.

```powershell
node --version
npm ci
# Только если своего .env ещё нет:
Copy-Item .env.example .env
npm start
```

Открыть http://localhost:8000. На Windows можно запустить start_windows.bat. Первый старт импортирует gzip CSV в var/app-node.sqlite3; дождаться завершения и оставить около 500 МБ свободного места. Последующие запуски используют базу. Изменение CSV автоматически её не перестраивает.

.env.example задаёт demo: ключ не нужен, модель не вызывается, ответы шаблонные. Уже существующий личный .env может включать live — проверить свой режим до нажатия генерации. Первые шесть новостей синтетические и помечены в интерфейсе.

| Команда | Назначение |
|---|---|
| npm start | Запустить сервер |
| npm run dev | Разработка с автоперезапуском |
| npm run typecheck | Проверка типов |
| npm test | 18 интеграционных тестов с подставными ответами модели |
| npm run build | Сборка TypeScript в dist/ |
| node dist/index.js | Запуск собранного сервера |

Редактировать сервер в server/*.ts. dist/*.js генерируется автоматически. frontend/app.js — самостоятельный исходник браузера.

## Что уже работает

- Загрузка компаний, платежей и связей; профиль и поиск компаний.
- Персональная лента на правилах, ручное добавление новостей, загрузка настроенных RSS/Atom.
- Лексический поиск по OCR девяти документов банка с номерами страниц и ссылками.
- Demo и live-агент, инструменты, проверка структуры/цитат, кеш анализов, уточняющие вопросы.
- Интерфейс и обработка основных ошибок.

Это не завершённая реализация всего командного плана. В частности, отсутствуют HTML-парсинг статей, обновление по расписанию, векторный поиск и полноценный гибридный RAG; ML-персонализация также ещё не сделана. Детальный статус — в TASKS.md.

## Live, данные и ограничения

Для настоящей модели задать LLM_MODE=live и LLM_API_KEY только в своём .env, затем перезапустить сервер. Модель и лимиты настраиваются через .env.example/config.ts. Новый анализ и вопросы могут расходовать API-бюджет; один анализ — до шести вызовов. Повторное открытие сохранённого анализа использует кеш.

Локальный лимит считает попытки, а не рубли; сброс в 00:00 МСК. Общий лимит организаторов, указанный в конфигурации кейса, — 500 рублей в день со сбросом в 03:00 МСК; локальный код не контролирует общий расход команды. Ключ не должен попадать в Git.

Исходные данные: 85 525 строк компаний (85 514 уникальных ID), 1 380 585 платежей, 12 514 связей; 9 документов банка, 64 OCR-страницы. Дубли компаний пока разрешаются последней строкой, самоплатежи включены в агрегаты. Единицы выручки и период/валюта платежей не подтверждены. Платёж не доказывает поставку, связь физлиц — владение. Есть документ 2021 года.

Формальная проверка источников не доказывает смысловую точность ответа. Приложение рассчитано на localhost: X-Company-ID выбирает компанию, но не является авторизацией. Проверка live-сценария на синтетической новости подтверждает работу цепочки, не качество всех выводов.

## Команда, Node.js и GitHub

Распределение ролей получено от команды; Матвей — роль 3. В её описании написано FastAPI. Локально выбран Node.js/Express: это предлагаемая замена серверного фреймворка, которую ещё нужно согласовать с командой. Оба позволяют сделать HTTP/JSON API; совместимость зависит от контракта, не названия языка.

Командный репозиторий: https://github.com/AzatBadretdinov/alfa-news-agent. Его Python company_context не является зависимостью приложения. Полезную логику профиля можно перенести на TypeScript в рамках роли 1. Второй Python-сервер локально не нужен. Коммиты, push и merge выполняет пользователь; автоматической синхронизации нет. Порядок передачи в отдельной ветке — в docs/TEAM_GUIDE.md.

## Docker и проверка

Создать свой .env, выполнить docker compose up --build. Порт опубликован только на localhost. Docker-конфигурация подготовлена, запуск пока не подтверждён. Проверки типов, 18 тестов и сборка ранее проходили; при изменении кода повторить их. Новые документы не означают, что перечисленные будущие задачи уже реализованы.
